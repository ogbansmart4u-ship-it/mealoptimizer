Personalized meal plans, AI food‑photo analysis, and a wellness suite (weight, hydration, sleep, symptoms, workouts, medications, reminders, goals, meal logs, achievements, Medical Vault). ### ⚠️ Backend editing rule (important)
The **live edge function is the source of truth**; the on‑disk copy is stale/diverged. To change the backend: `get_edge_function` (fetch live) → edit the exact handler → `deploy_edge_function` (both `index.tsx` + `kv_store.tsx`) → re‑fetch and verify (md5 or key markers). Supabase validates/bundles on deploy, so a syntax error is rejected rather than breaking production. When re‑emitting the file, note the two comment lines with em‑dashes (`—`) — harmless if they become hyphens.

## 1. WHAT'S ALREADY LIVE (no push needed)

**Backend edge function `make-server-ba6f1f45` v62** — the `/ai/generate-single-meal` handler was rewritten across three deploys:

- **v60:** replaced the single hardcoded fallback meal (grilled tilapia — was returned identically to every user) with a **per‑user‑seeded pool of local meals** per meal type; added a per‑request **variation token** + **Sex** to the prompt.
- **v61:** computes a **per‑meal calorie target** from the profile (Mifflin‑St Jeor: weight + height‑from‑BMI + age + sex, ×1.4 activity, ±goal for lose/gain, split by meal type: breakfast 25% / brunch 30% / lunch 35% / dinner 30% / snack 12%) and anchors each meal within ~10% of it.
- **v62:** accepts an **`exclude`** array (meal names already shown) and instructs the AI **not to repeat them**; raised temperature 0.7 → **0.95** (topK 60, topP 0.98); added a dedicated **`brunch`** fallback pool (previously borrowed lunch's).

Net effect once the frontend below is pushed: for any meal type, tapping generate repeatedly yields **genuinely different dishes at similar, profile‑appropriate calories**.
